# Frontend — «Ключ к доверию»

Стек: React 19 + TypeScript + Vite + Tailwind CSS v4.

Игра и админ-панель — одно и то же React-приложение. Весь игровой
контент (10 сценариев, варианты ответов, тексты уровней результата)
загружается с backend через API, а не хранится статично во фронтенде —
это специально сделано так, чтобы куратор мог менять тексты через
`/admin`, не трогая код и не пересобирая проект.

## Запуск локально

Backend должен быть уже запущен (см. `../backend/README.md`) —
по умолчанию фронтенд ждёт его на `http://localhost:8000`. Если backend
работает на другом адресе, поменяй `VITE_API_URL` в `.env` (см.
`.env.example`).

```bash
cd frontend
npm install
npm run dev
```

Откроется адрес `http://localhost:5173` — сама игра.
Админ-панель — `http://localhost:5173/admin` (логин `admin` / `admin123`
по умолчанию).

## Структура

```
src/
  types.ts                    — типы сценария и варианта ответа
  constants.ts                — внешние ссылки (страница выставки, покупка билета)

  api/
    client.ts                 — обёртка над fetch: базовый адрес API, JWT-заголовок, ошибки
    game.ts                   — запросы игры: GET /api/scenarios, сессии, ответы, финиш

  screens/                    — экраны самой игры
    LandingScreen.tsx           стартовый экран
    ScenarioScreen.tsx           экран одного сценария (принимает уже загруженные данные)
    AnswerScreen.tsx             экран после выбора ответа (баллы + объяснение)
    ResultScreen.tsx              финальный экран: индекс, уровень, промокод, "поделиться"
    MemoScreen.tsx                памятка по цифровой безопасности

  components/                 — общие для игры компоненты (TopBar, Footer, PhoneScreen и т.д.)
    visuals/                     карточки-иллюстрации под каждый тип сценария

  admin/                      — админ-панель (отдельная часть приложения, /admin)
    AdminApp.tsx                 переключатель экранов админки
    api.ts                       все запросы к /api/admin/...
    components/                  TopNav (верхняя навигация), графики (Donut/Line)
    screens/
      LoginScreen.tsx             вход
      OverviewScreen.tsx          обзорная статистика (прохождения, ошибки, профили)
      AnswerStatsScreen.tsx       статистика по ответам на каждый сценарий
      ScenariosListScreen.tsx     список сценариев
      ScenarioEditScreen.tsx      редактирование сценария (включая загрузку фото)
      ProfilesScreen.tsx          редактирование текстов уровней результата (новичок/знаток/эксперт)

  App.tsx                    — весь игровой поток: грузит сценарии и сессию с backend,
                                ведёт игрока по сценариям, отправляет ответы, дожидается
                                финального результата с backend перед показом ResultScreen
```

## Откуда что берётся (важно при отладке)

- **Сценарии, варианты ответов, объяснения** — `GET /api/scenarios`.
  Если что-то не совпадает с тем, что видно в игре, проверяй базу
  (через `/admin`), а не код: во фронтенде своей копии этих текстов
  больше нет.
- **Итоговый балл и текст уровня результата** (`ResultScreen`) —
  считается и хранится на backend, отдаётся в ответе
  `POST /api/sessions/{id}/finish`. Правки текста уровня в
  `/admin` → «Профили» долетают до игрока именно через этот ответ.
  Если backend в момент финиша недоступен — показывается общий
  запасной текст (см. `FALLBACK_TIER` в `App.tsx`), а не старый текст
  из кода: специально сделано так, чтобы не было двух источников
  правды, которые могут разойтись.
- **Фото сценария в админке** — если куратор загрузил кастомное фото
  через `/admin`, `ScenarioScreen` показывает именно его вместо
  встроенной иллюстрации (см. `imageUrl` у сценария).

## Переменные окружения

См. `.env.example`. Единственная сейчас — `VITE_API_URL`, адрес backend.
