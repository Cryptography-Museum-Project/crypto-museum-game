# Маршрут цифрового дня

Интерактивная игра для выставки Музея криптографии «Ключ к доверию. Безопасность в эпоху высоких технологий» (экспертный партнёр — компания «Бастион»).

Посетитель проходит 10 ситуаций цифрового дня, получает индекс цифровой безопасности от 0 до 100, профиль (новичок / знаток / эксперт) и памятку. Сотрудники музея смотрят обезличенную статистику и редактируют сценарии в админ-панели.

**Стек:** React 19 + TypeScript + Vite + Tailwind CSS v4 (фронтенд), Python 3.11 + FastAPI + SQLAlchemy + SQLite (бэкенд), Docker Compose + nginx (запуск).

## 1. Быстрый запуск через Docker

Так запускается всё приложение целиком: игра, админ-панель и сервер. **Node.js, Python и `npm install` для этого не нужны** — всё ставится внутри Docker автоматически.

### Что установить

| Программа | Где взять | Зачем |
|---|---|---|
| Git | https://git-scm.com/downloads | скачать проект |
| Docker Desktop (Windows / Mac) или Docker Engine (Linux) | https://www.docker.com/products/docker-desktop/ | запустить проект |

После установки Docker Desktop **откройте его и дождитесь**, пока он полностью загрузится (внизу окна появится зелёная надпись *Engine running*). Docker Desktop не запускается сам — его нужно открывать перед каждой работой с проектом.

Проверка: откройте терминал (на Windows — PowerShell, на Mac — Terminal) и выполните:

```
git --version
docker --version
```

Обе команды должны показать номер версии, а не ошибку.

### Запуск

```
git clone https://github.com/Cryptography-Museum-Project/crypto-museum-game.git
cd crypto-museum-game
docker compose up --build -d
```

Первый запуск занимает 2–5 минут (скачиваются и собираются образы). Следующие — несколько секунд.

Команда завершится и вернёт управление терминалу — это нормально, приложение продолжает работать в фоне.

### Что открыть в браузере

| Что | Адрес |
|---|---|
| Игра | http://localhost:8080 |
| Админ-панель | http://localhost:8080/admin |
| Документация API (Swagger) | http://localhost:8080/docs |

Вход в админ-панель при локальном запуске: логин `admin`, пароль `admin123`. Для сервера пароль нужно задать свой — см. [раздел 3](#3-администратор-и-пароль).

При первом запуске база данных создаётся автоматически и заполняется 10 стартовыми сценариями.

## 2. Запуск на сервере

### Требования к серверу

- Linux (например, Ubuntu 22.04 / 24.04) с установленными Docker Engine и плагином Docker Compose
- Рекомендуется: 1 vCPU, 1 ГБ RAM, 5 ГБ диска
- Отдельная база данных не нужна: используется SQLite (один файл внутри Docker-тома)

### Шаги

1. Скачать проект:
   ```
   git clone https://github.com/Cryptography-Museum-Project/crypto-museum-game.git
   cd crypto-museum-game
   ```

2. Создать файл настроек из шаблона:
   ```
   cp .env.example .env
   ```

3. Открыть `.env` в любом текстовом редакторе (например, `nano .env`) и заменить значения:

   | Параметр | Что указать |
   |---|---|
   | `APP_PORT` | порт, на котором откроется сайт. Обычно `80`, или внутренний порт, если перед приложением стоит свой прокси с HTTPS |
   | `JWT_SECRET` | длинная случайная строка. Получить: `python3 -c "import secrets; print(secrets.token_hex(32))"` |
   | `ADMIN_DEFAULT_USERNAME` | логин администратора |
   | `ADMIN_DEFAULT_PASSWORD` | надёжный пароль администратора (не короче 12 символов) |

   **Сделайте это до первого запуска.** Администратор создаётся из этих значений только один раз — когда база ещё пустая.

4. Запустить:
   ```
   docker compose up --build -d
   ```

5. Проверить: открыть в браузере `http://<адрес сервера>:<APP_PORT>` и `/admin`.

### HTTPS

Само приложение отдаёт обычный HTTP. Для HTTPS поставьте перед ним обратный прокси с сертификатом (nginx, Caddy, Traefik или прокси хостинга) и направьте его на `http://localhost:<APP_PORT>`.

### Как устроено

Запускаются два контейнера:

- **frontend** — nginx. Отдаёт собранную игру и админку, а запросы `/api`, `/uploads`, `/docs`, `/openapi.json` передаёт в бэкенд. Это единственный контейнер с открытым наружу портом.
- **backend** — FastAPI. Наружу не открыт.

Данные хранятся в Docker-томах и не пропадают при перезапуске, пересборке и обновлении:

- `db_data` — база данных (сценарии, статистика, администратор)
- `uploads_data` — фото сценариев, загруженные через админку

## 3. Администратор и пароль

- Регистрации нет. Есть одна учётная запись администратора, которая создаётся при **первом** запуске из `ADMIN_DEFAULT_USERNAME` и `ADMIN_DEFAULT_PASSWORD`.
- Пароль хранится в базе только в виде bcrypt-хеша.
- После входа выдаётся токен, который действует `JWT_EXPIRE_MINUTES` минут (по умолчанию 240), затем нужно войти снова.

**Важно:** если поменять пароль в `.env` после первого запуска, он **не применится** — администратор уже есть в базе. Чтобы сменить пароль у работающего приложения, выполните в папке проекта (подставьте свой пароль):

```
docker compose exec backend python -c "from app.database import SessionLocal; from app.models import AdminUser; from app.security import hash_password; db=SessionLocal(); a=db.query(AdminUser).first(); a.password_hash=hash_password('НОВЫЙ_ПАРОЛЬ'); db.commit(); print('ok')"
```

Если после команды появилось `ok` — пароль изменён.

## 4. Обновление, остановка, резервная копия

Все команды выполняются в папке проекта `crypto-museum-game`.

| Задача | Команда |
|---|---|
| Посмотреть, запущено ли | `docker compose ps` |
| Посмотреть логи | `docker compose logs -f` (выйти — `Ctrl + C`) |
| Остановить | `docker compose down` |
| Запустить снова | `docker compose up -d` |
| Обновить до новой версии | `git pull` и затем `docker compose up --build -d` |
| Сделать копию базы | `docker compose cp backend:/app/data/game.db ./game-backup.db` |

Остановка, перезапуск и обновление **не удаляют** данные.

**Никогда не выполняйте `docker compose down -v`** — флаг `-v` удаляет тома, то есть всю статистику, изменения сценариев и загруженные фото.

В логах каждые 10 секунд появляются строки `GET /health 200 OK` — это Docker проверяет, что сервер работает. Это нормально.

### Сценарии и контент

Сценарии, варианты ответов, баллы, объяснения, фото и тексты профилей редактируются в админ-панели (`/admin` → «сценарии» / «профили») и сразу применяются в игре.

Файл `backend/app/seed_data.py` содержит стартовые сценарии и используется **только при создании пустой базы**. Изменения в нём не повлияют на уже работающее приложение.

## 5. Запуск для разработки

Этот режим нужен только тем, кто меняет код: изменения во фронтенде видны в браузере сразу, без пересборки.

Дополнительно к Git и Docker установите **Node.js версии 20.19 или новее** (LTS): https://nodejs.org/. Проверка: `node --version`.

### Шаг 1. Установить зависимости фронтенда (один раз)

```
cd crypto-museum-game/frontend
npm install
```

Повторять `npm install` нужно после каждого `git pull`, если в нём изменился `package.json`, и при работе с новой копией проекта.

> Если VS Code подчёркивает импорты красным с ошибкой `Cannot find module 'react'` — значит, `npm install` в папке `frontend` ещё не выполнялся. После установки, если ошибка не ушла: `Ctrl + Shift + P` → `TypeScript: Restart TS Server`.

### Шаг 2. Запустить бэкенд

В первом окне терминала:

```
cd crypto-museum-game/backend
docker compose up --build
```

Дождитесь строки `Uvicorn running on http://0.0.0.0:8000`. Окно не закрывайте. Проверка: http://localhost:8000/docs.

### Шаг 3. Запустить фронтенд

Во **втором** окне терминала:

```
cd crypto-museum-game/frontend
npm run dev
```

| Что | Адрес |
|---|---|
| Игра | http://localhost:5173 |
| Админ-панель | http://localhost:5173/admin (`admin` / `admin123`) |

Остановить: `Ctrl + C` в каждом окне.

Фронтенд по умолчанию обращается к бэкенду на `http://localhost:8000`. Если бэкенд на другом адресе — создайте `frontend/.env` по образцу `frontend/.env.example` и укажите `VITE_API_URL`.

У режима разработки **своя отдельная база**, не та, что у запуска из раздела 1.

### Проверка перед коммитом

```
cd frontend
npx tsc -b --noEmit
npm run build
```

## 6. Структура проекта

```
crypto-museum-game/
├── docker-compose.yml     # полный запуск: frontend (nginx) + backend
├── .env.example           # шаблон настроек для полного запуска
├── backend/
│   ├── app/
│   │   ├── main.py        # точка входа FastAPI
│   │   ├── config.py      # настройки (из переменных окружения)
│   │   ├── models.py      # таблицы базы данных
│   │   ├── schemas.py     # формат запросов и ответов API
│   │   ├── security.py    # хеширование пароля, JWT
│   │   ├── seed_data.py   # стартовые сценарии и профили для пустой базы
│   │   └── routers/       # эндпоинты API (игра, статистика, админка)
│   ├── Dockerfile
│   ├── docker-compose.yml # запуск только бэкенда — для разработки
│   └── README.md          # подробно о бэкенде, API и базе данных
└── frontend/
    ├── src/               # игра (src/screens) и админ-панель (src/admin)
    ├── public/            # шрифты, иконка
    ├── Dockerfile         # сборка и раздача через nginx
    ├── nginx.conf
    └── README.md          # подробно о фронтенде
```

Полное описание API — в Swagger по адресу `/docs` запущенного приложения.

## 7. Если что-то не работает

| Проблема | Что делать |
|---|---|
| `docker` не найден или ошибка про WSL / `cannot connect to the Docker daemon` | Откройте Docker Desktop и дождитесь *Engine running*, затем повторите команду. На Windows при первой установке может понадобиться перезагрузка. |
| `port is already allocated` | Порт занят другой программой или второй копией проекта. Остановите её (`docker compose down` в её папке) или задайте другой `APP_PORT` в `.env`, например `8081`. |
| `No such image` на Windows | Docker Desktop → Settings → General → снять галочку *Use containerd for pulling and storing images* → Apply & restart. |
| Остались старые контейнеры после переключения между версиями | `docker compose down --remove-orphans`, затем `docker container prune -f`. |
| Игра пишет «не удалось связаться с сервером» | Проверьте `docker compose ps`: оба контейнера должны быть в статусе *running* / *healthy*. Логи бэкенда: `docker compose logs backend`. |
| Не пускает в админку с паролем из `.env` | Пароль из `.env` применяется только к пустой базе. Смените его командой из [раздела 3](#3-администратор-и-пароль). |
| `Cannot find module 'react'` в VS Code, `npm run dev` не запускается | Выполните `npm install` в папке `frontend` (см. [раздел 5](#5-запуск-для-разработки)). |
