# Ключ к доверию — Backend

Бэкенд для интерактивной игры «Маршрут цифрового дня» (выставка Музея
криптографии «Ключ к доверию. Безопасность в эпоху высоких технологий»,
партнёр — компания «Бастион»).

Отдаёт фронтенду 10 игровых сценариев, принимает ответы посетителей,
считает индекс цифровой безопасности (0–100) и определяет уровень
(«новичок» / «знаток» / «эксперт»). Для музея хранит **обезличенную**
статистику прохождений и отдаёт её в админ-панель.

## Стек

- **Python 3.11 + FastAPI** — веб-фреймворк
- **SQLAlchemy 2.0** — работа с базой данных
- **SQLite** — сама база данных (это просто файл `game.db`, не нужно
  ставить отдельный сервер БД)
- **JWT (python-jose) + passlib/bcrypt** — авторизация в админке
- **Docker** — для запуска на сервере одной командой

## Локальный запуск (без Docker)

Понадобится Python 3.11+ (подойдёт и 3.10/3.12).

```bash
# 1. Перейти в папку проекта
cd crypto-museum-backend

# 2. Создать виртуальное окружение (изолированное место для библиотек проекта)
python3 -m venv .venv

# 3. Активировать его
source .venv/bin/activate        # Windows: .venv\Scripts\activate

# 4. Установить зависимости
pip install -r requirements.txt

# 5. Запустить сервер
uvicorn app.main:app --reload
```

После этого:
- API доступно на `http://localhost:8000`
- Автоматическая документация (Swagger) — на `http://localhost:8000/docs`.
  Там можно сразу нажимать "Try it out" и проверять любой эндпоинт руками,
  без Postman и curl.

При первом запуске сервер сам создаст файл `game.db` и заполнит его
10 сценариями, 3 уровнями и одним админом (`admin` / `admin123`).

## Запуск через Docker (рекомендуется для сервера)

Понадобится установленный Docker и Docker Compose.

```bash
cd crypto-museum-backend
cp .env.example .env      # при желании поменяй пароли внутри .env
docker compose up --build
```

API поднимется на `http://<адрес-сервера>:8000`, данные (файл базы)
сохраняются в Docker volume и не пропадут при перезапуске контейнера.

Остановить: `docker compose down` (данные останутся).
Остановить и удалить вообще всё, включая базу: `docker compose down -v`.

### Требования к серверу

- 1 CPU, 512 МБ RAM — с запасом достаточно (SQLite и один процесс FastAPI —
  очень лёгкая связка для нагрузки уровня музейной выставки).
- Установленный Docker Engine + Docker Compose plugin.
- Открытый порт 8000 (или другой — можно поменять в `docker-compose.yml`).
- Если бэкенд и фронтенд на разных доменах — не забыть указать домен
  фронтенда в `CORS_ALLOW_ORIGINS` в `.env`.

## Структура базы данных

| Таблица | Что хранит |
|---|---|
| `scenarios` | 10 игровых сценариев (текст ситуации, категория, картинка-визуал) |
| `scenario_options` | варианты ответа для каждого сценария (текст, баллы 0/5/10, объяснение) |
| `tiers` | 3 уровня результата: новичок / знаток / эксперт (границы индекса и тексты) |
| `sessions` | одно прохождение игры одним посетителем: когда начал, когда закончил, итоговый балл. **Без имени, телефона, email — ничего личного не хранится** |
| `session_answers` | какие варианты ответа выбрал посетитель в рамках сессии |
| `admin_users` | логины/пароли (в виде хеша) для входа в `/admin` |

## Описание API

Полная и всегда актуальная спецификация — в Swagger по адресу `/docs`
(или `/openapi.json` для машинного формата). Ниже — краткая шпаргалка.

### Публичная часть (для самой игры)

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/api/scenarios` | Список из 10 активных сценариев с вариантами ответов |
| POST | `/api/sessions` | Начать новое прохождение → возвращает `id` сессии |
| POST | `/api/sessions/{id}/answers` | Отправить ответ на один сценарий (`scenarioId`, `optionId`) |
| POST | `/api/sessions/{id}/finish` | Завершить игру → итоговый балл (0-100) и уровень |

Все ответы — в camelCase (`optionsHeading`, `totalScore` и т.д.), то есть
ровно в том же формате, в каком фронтенд уже ждёт данные в
`src/types.ts`.

### Админка

| Метод | Путь | Что делает |
|---|---|---|
| POST | `/api/admin/login` | Вход, возвращает JWT-токен |
| GET | `/api/admin/me` | Кто сейчас залогинен |
| POST | `/api/admin/me/password` | Сменить свой пароль |
| GET | `/api/admin/scenarios` | Все сценарии (включая отключённые) — для редактирования |
| PATCH | `/api/admin/scenarios/{id}` | Изменить сценарий и его варианты ответа |
| GET | `/api/admin/tiers` | Все 3 уровня |
| PATCH | `/api/admin/tiers/{key}` | Изменить описание уровня (`key`: novice / connoisseur / expert) |
| GET | `/api/admin/stats/overview?period=today\|7d\|30d\|all` | Общие цифры: количество прохождений, средний индекс, % завершения, среднее время |
| GET | `/api/admin/stats/scenarios` | Статистика по каждому сценарию: % ошибок, % выбора каждого варианта |
| GET | `/api/admin/stats/profiles` | Доля посетителей в каждом уровне (новичок/знаток/эксперт) |
| GET | `/api/admin/stats/mistakes` | Топ самых частых "не лучших" ответов по всем сценариям |

Все `/api/admin/...` эндпоинты (кроме `/login`) требуют заголовок:
```
Authorization: Bearer <токен, полученный из /login>
```

## Как посмотреть статистику, не разбираясь в API

Проще всего — зайти на `/docs`, нажать на `POST /api/admin/login`,
"Try it out", ввести логин/пароль, скопировать `access_token` из ответа,
нажать на кнопку **Authorize** вверху страницы и вставить токен туда
(формат: просто сам токен, без слова Bearer — Swagger добавит его сам).
После этого все `/api/admin/...` эндпоинты можно вызывать прямо со
страницы `/docs`, не устанавливая ничего дополнительно.

## Как изменить тексты сценариев

Два способа:

1. **Через API** (когда админка на фронтенде будет подключена к этому
   бэкенду) — `PATCH /api/admin/scenarios/{id}`.
2. **Прямо в коде**, если правишь один раз до передачи заказчику:
   открой `app/seed_data.py`, поменяй нужный текст в списке `SCENARIOS`
   или `TIERS`, удали файл `game.db` (или том Docker) и перезапусти
   сервер — он создаст базу заново с новыми текстами.
   ⚠️ Способ 2 стирает уже накопленную статистику, поэтому годится
   только для этапа разработки, не для музея "в бою".

## Что дальше (не входит в эту версию, но стоит знать)

- **Подключение фронтенда к этому API.** Сейчас фронтенд работает
  полностью на статичных данных из `src/data/scenarios.ts` — реальных
  запросов к серверу нет ни одного. Формат ответов API специально
  сделан идентичным `src/types.ts`, так что интеграция — это в
  основном "заменить локальный массив на `fetch('/api/scenarios')`" в
  паре мест плюс подключить `POST /api/sessions/...` в игровой поток и
  реальный логин в `LoginScreen`.
- **Alembic** (миграции базы данных) — сейчас база создаётся простым
  способом (`create_all`). Для учебного/выставочного проекта с одной
  базой SQLite это нормально. Если появится необходимость менять
  структуру таблиц на уже заполненной "боевой" базе без потери данных —
  тогда стоит добавить Alembic.
- **Промокод.** Сейчас промокод (`59FG-SDFG-DGK9`) один и тот же для
  всех, зашит прямо во фронтенде — бэкенд в этом не участвует. Если
  понадобятся уникальные/одноразовые промокоды — это отдельная
  небольшая доработка (таблица кодов + эндпоинт "выдать код").
